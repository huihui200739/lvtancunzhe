# 项目说明

当前权威事实入口；版本1.2.0，数据库schema2。

## 解决的问题与用户路径

使用者记录真实发生的局部低碳行为，查看“相对哪个情景、使用哪个因子、结果和来源是什么”，再按时间和预算安排接下来七天。用户申报的数量没有独立核实，应用不声称统计了完整个人碳足迹。

五个主页面：存折（录入与凭证）、计划（目标和约束）、看板（统计）、知绿（12篇离线文章及自绘示意图）、我的（积分、虚拟奖励、数据管理）。

## 核心能力

**可追溯凭证**：保存记录版本、情景输入、因子代码/版本/来源、气体口径、计算结果及边界。修订保留旧版，撤销写入冲正，正式备份恢复会核对来源和复算快照。

**可解释七日计划与行动教练**：结合目标、单一气体口径、时间/费用预算、可用日期、出行习惯和愿意尝试的类别，从任务模板筛选安排并展示推荐原因。计划页“今天先做”只读取已保存计划里的今日起七日内未完成任务，点击进入现有记录/参与路径；不会自动完成或生成记录。预计贡献、实际记录和参与奖励分开；无适配因子的任务仅记录参与，不虚计kg。

**隐私七日周报**：用户主动查看并保存本地文本汇总，按CO₂和CO₂e分列，含周期、有效记录数、分类结果与估算边界；不输出记录编号、备注或身份信息。

**可选 AI 补充建议（1.2.0）**：默认关闭。使用者自行配置 OpenAI 兼容接口地址、模型与 API Key，开启后仅发送已保存计划的公开摘要（窗口、目标、预计值、任务标题/类别/日期），返回的文本只作执行提醒，不参与核算、凭证、积分或目标判断；密钥只保存在本机应用沙箱偏好文件，不进入账本、备份、CSV 或日志。应用因此声明了 `ohos.permission.INTERNET`，但未开启时全部功能离线可用。

**拍照辅助记账**：存折页“拍照记一笔”调用系统相机或相册选图（模拟器可用演示样张），用 MindSpore Lite 端侧运行 MobileNetV2（Open Images 410 类，模型来源与哈希见 `rawfile/model/README.txt`）识别画面里可能有什么，只据此建议打开哪张存入单（出行/少买/废纸/省电）。不识别数量、不判断行为真实性、不参与核算；拍到汽车/公交不推断为减排。识别全程离线。模型 11MB 不纳入 Git，克隆后运行 `bash scripts/fetch-model.sh` 下载并校验哈希；模拟器演示样张及授权见 `rawfile/samples/CREDITS.txt`。

**任务日历提醒**：计划页“今天先做”每项任务可“加入日历”，拉起系统日历新建页预填当天 19:00 与说明，由用户在日历里确认保存；只排未完成且未过时的任务。

**七日分享卡**：我的页“生成分享卡”把近七天按分口径合计渲染成图，经系统安全控件（仅本次点击授权）保存到相册；不含记录编号、备注或身份信息，卡面带估算边界说明。

**碳普惠平台（模拟）**：凭证可转存到本机模拟平台，按 10 分/kg 换算模拟积分并兑换虚构权益，生成 `DEMO-` 兑换码；按记录版本与请求号幂等。数据只存本机偏好文件，不联网、不进账本备份或 CSV，不代表真实平台、权益或经核证碳资产。

七日计划和行动教练采用本地确定性规则，不是云端大模型或机器学习推荐。端侧图像分类只用于建议存入单类别；OCR未接入；项目由AI辅助开发不等于产品内所有功能都有AI推理。

## 架构与代码定位

| 层次 | 位置与职责 |
|---|---|
| 页面与共用组件 | `entry/src/main/ets/pages`、`components`：ArkUI呈现与用户交互 |
| 核算与规划 | `services/CalcEngine.ets`、`PlanEngine.ets`：核算、过滤和任务组合 |
| 行动与分享 | `services/ActionCoachService.ets`、`WeeklyReportService.ets`：只读行动建议与隐私汇总 |
| 模拟平台 | `services/MockBenefitPlatform.ets`、`pages/BenefitPage.ets`：本机偏好文件中的模拟转存与兑换，不写账本 |
| 拍照记一笔 | `services/PhotoRecognizer.ets`（MindSpore Lite 推理）、`PhotoAssist.ets`（纯函数建议）、`pages/PhotoAssistPage.ets`、`data/OpenImage*.ets` |
| 提醒与分享 | `services/TaskReminderService.ets`（系统日历）、`ShareCardService.ets`、`pages/ShareCardPage.ets`（安全控件保存相册） |
| 可选 AI | `services/AiConfigStore.ets`、`AiCoachService.ets`、`pages/AiSettingsPage.ets`：本机密钥、计划摘要请求与可读错误 |
| 业务操作 | Record/Point/Reward/Plan等Service：记录、积分、兑换及任务联动 |
| 操作一致性 | `services/LedgerOperations.ets`：前置校验到提交的完整操作排队，避免并发交叉 |
| 数据库与快照 | `services/LedgerDb.ets`、`LedgerSchema.ets`：本地RDB、版本和冻结凭证 |
| 正式方法 | `data/ProdFactors.ets`、`ReviewedBehaviorFactors.ets`：来源、单位、范围及限定条件 |
| 导出与恢复 | BackupService/BackupPolicy/CsvService：JSON备份、校验恢复及CSV |

数据保存在本地。没有本项目的账号服务器、云同步或碳交易接口；GitHub用于团队代码协作，不是应用后端。1.2.0 的 AI 功能由使用者自带密钥直连其配置的第三方接口，不由本项目托管任何密钥或中转数据。

## 版本与验收边界

78项本地自动业务回归通过（59项原有基线 + 19项特色服务用例）；云端CI模板待管理员启用。2026-11-03已在API24 Pura90模拟器点击验证行动教练、周报保存、模拟回执与 AI 设置/失败提示；未做物理真机与全部屏幕尺寸验收。原生历史验收包括API24手机模拟器上的既有主流程、计划关联、恢复、导航、字号与动效；没有真实手机全量验收、所有屏幕尺寸覆盖或大数据压力测试。原生自检界面为11通过、3跳过；与75项Node回归是不同测试集。2026-11-04已在API24模拟器点击验收：模型元信息 chips（该中转站未返回元数据，chips 如实只显示模型名）、周/月视图最近区间chips「更多 N / 收起」展开与跳转筛选、AI 建议「复制文本 / 存为周报备注」及周报弹窗带出 AI 备注并保存文本回读。中转站元数据展示路径仅有单测覆盖（该站 /models 不返回这些字段）。
