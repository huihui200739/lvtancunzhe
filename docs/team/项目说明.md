# 项目说明

当前权威事实入口；版本1.1.3，数据库schema2。

## 解决的问题与用户路径

使用者记录真实发生的局部低碳行为，查看“相对哪个情景、使用哪个因子、结果和来源是什么”，再按时间和预算安排接下来七天。用户申报的数量没有独立核实，应用不声称统计了完整个人碳足迹。

五个主页面：存折（录入与凭证）、计划（目标和约束）、看板（统计）、知绿（12篇离线文章及自绘示意图）、我的（积分、虚拟奖励、数据管理）。

## 两项亮点

**可追溯凭证**：保存记录版本、情景输入、因子代码/版本/来源、气体口径、计算结果及边界。修订保留旧版，撤销写入冲正，正式备份恢复会核对来源和复算快照。

**可解释七日计划**：结合目标、单一气体口径、时间/费用预算、可用日期、出行习惯和愿意尝试的类别，从任务模板中筛选安排，展示推荐原因。预计贡献、实际记录和参与奖励分开；计划不自动生成完成记录。无适配因子的任务仅记录参与，不虚计kg。

计划使用本地规则与组合选择，不是云端大模型或机器学习推荐。项目由AI辅助开发不等于产品内有AI推理。

## 架构与代码定位

| 层次 | 位置与职责 |
|---|---|
| 页面与共用组件 | `entry/src/main/ets/pages`、`components`：ArkUI呈现与用户交互 |
| 核算与规划 | `services/CalcEngine.ets`、`PlanEngine.ets`：核算、过滤和任务组合 |
| 业务操作 | Record/Point/Reward/Plan等Service：记录、积分、兑换及任务联动 |
| 操作一致性 | `services/LedgerOperations.ets`：前置校验到提交的完整操作排队，避免并发交叉 |
| 数据库与快照 | `services/LedgerDb.ets`、`LedgerSchema.ets`：本地RDB、版本和冻结凭证 |
| 正式方法 | `data/ProdFactors.ets`、`ReviewedBehaviorFactors.ets`：来源、单位、范围及限定条件 |
| 导出与恢复 | BackupService/BackupPolicy/CsvService：JSON备份、校验恢复及CSV |

数据保存在本地。没有本项目的账号服务器、云同步或碳交易接口；GitHub用于团队代码协作，不是应用后端。
