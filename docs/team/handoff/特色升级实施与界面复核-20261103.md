# 特色升级实施与界面复核（2026-11-03，1.2.0）

> 本记录只描述本轮实际写入工程并完成的验证，不替代比赛负责人对报名、人工试用和材料提交状态的确认。

## 已完成

### 1. 低碳行动教练

- 新增 `ActionCoachService`，仅从已保存的七日计划中整理今日起七天内最多三项未完成任务。
- 采用可解释、确定性的本地规则：日期、进行中状态、额外时间/费用、预计值和任务编号参与排序；不使用云端服务、模型推理或随机数。
- 计划页新增“今天先做”卡片。点击只进入既有录入/参与路径并传递任务身份；不会自动完成、自动生成记录或重复计入减排量。

### 2. 隐私友好七日周报

- 新增 `WeeklyReportService`，按统计服务已有的筛选逻辑生成七日文本摘要。
- CO₂ 与 CO₂e 分列统计；包含周期、记录数、分类净变化和免责声明。
- 不输出记录编号、备注、姓名、学号、照片、位置或其他身份字段。
- “我的”页支持用户主动预览并通过系统文件保存入口保存文本；取消预览不产生文件，不写入数据库。

### 3. 离线碳普惠接口演练

- 新增 `LocalMockBenefitService`，只接收当前凭证中“最新、有效、正向、来源已核验”的估算结果。
- 提供模拟提交、幂等查询和拒绝原因；回执只保存在本次应用进程内。
- 凭证页明确提示：不会联网、不会上报真实平台、不会写入账本或增加积分，不是平台交易或经核证碳资产。
- 未新增数据库表、字段、网络权限、真实平台接口或多设备同步。

### 4. 端侧图片 AI 技术门结论

本轮不接入图片 OCR、分类模型或图片权限。当前工程没有目标 OpenHarmony API 24/26 的已验证推理入口、模型依赖、模型/样本许可记录或原生图片测试。官方 Core Vision 资料不能单独证明本工程目标环境可用，也不能证明完全离线。因此保留现有手动录入流程，不把 `IMAGE_ASSISTED` 标签包装成已实现的 AI 识别。

后续如重启该方向，必须先做 API 24 与 API 26 隔离技术探针，验证断网冷启动、权限拒绝/取消、异常图片、模型许可和真实性确认流程；识别结果不得自动入账。

## 5. 可选 AI 补充建议（1.2.0 新增）

- 新增 `models/AiModels.ets`、`services/AiConfigStore.ets`、`services/AiCoachService.ets`、`pages/AiSettingsPage.ets`。
- 默认关闭；使用者自行填写 OpenAI 兼容接口地址（必须 https）、模型名与 API Key，并可一键测试连通。
- 只发送已保存计划的公开摘要：计划窗口、目标/差额、参与任务数、任务标题/类别/日期/预计值；**不发送**记录编号、备注、姓名、学号、积分明细或数据库文件。
- AI 文本只作执行提醒，不参与核算、凭证、积分与目标判断；界面标注模型名与“AI 生成，仅供参考”。
- 密钥存于应用沙箱 `preferences`，不写 RDB、不进入备份/CSV/日志；提供清除入口。
- 支持中转站：可直接填根地址，保存与请求时自动补 `/v1/chat/completions`；模型名以后台模型列表为准（本次实测的中转站对未知模型返回 404，已把提示写清楚）。
- `module.json5` 声明 `ohos.permission.INTERNET`；未开启 AI 时全部功能离线可用，失败时保留本地功能并给出可读错误。

## 界面方向与复核

本轮保留已有的“校园纸本账簿 + 植物生长”方向：暖灰纸面、深墨绿主色、少量嫩绿作为数字重点，信息层级通过尺寸/留白建立；不使用紫蓝渐变、发光、机器人/AI装饰、emoji 图标或泛化的“智能”宣传词。首页和五个 Tab 使用已有产品内容作为视觉重点：可追溯凭证数字、行动建议卡、统计图表、离线文章和本地数据管理。

复核清单：

- 表面使用单一低饱和中性 ramp，绿色综合色只承担主操作/重点数字/选中状态。
- 页面间距主要使用 4px 节奏，卡片/面板/控件半径由 `Theme` 统一。
- 图标使用项目自有扁平资源，不以 emoji 代替图标；保留大字体和可关闭动效能力。
- 文案不使用无法证明的 AI、真实平台、真实碳资产或完整个人足迹表述。
- 本地 release 编译成功；2026-11-03 已在 API24 Pura 90 模拟器完成点击验收，明细见[验收记录](../验收记录.md)。

### 本轮具体执行的观感修正（代码层）

依据现有页面与旧截图（`docs/ui-review/`，早于本轮代码，不能当作当前界面证据）做了一次“减少装饰、强化账本感”的定稿式调整：

| 修正 | 位置 | 原因 |
|---|---|---|
| 四类行动入口由四种浅色调改为纸面 + 发行细线 | `LedgerTab.categoryTile`、`recordCard` 图标底 | 四块相近的粉彩像通用 App 宫格；统一纸面后只剩主色与数字承担强调 |
| 删除未再使用的分类浅色函数 | `common/Theme.ets` | 避免无出处的装饰色残留 |
| 首页主标题改为“每笔记录 / 都留有依据” | `LedgerTab` | 说明这款产品做什么（账本留证），而非泛化口号 |
| 关键金额/积分数字启用等宽数字（tabular） | 存折、看板、凭证、我的 | 不同位数下数字列对齐，避免跳动 |
| 计划“今天先做”卡去掉与下方任务卡重复的长理由，只留任务、日期与预计 | `PlanTab.actionRecommendationCard` | 同一理由在一屏出现两次；详情仍保留在任务卡 |
| 计划日期分组改为“今天 · 周一 / 11-03 · 周二” | `PlanTab.dayLabel` | 按日程扫读更接近纸质计划 |
| 看板汇总标签由 Bold 改 Medium | `DashboardTab.SummaryCell` | 层级用字号建立，不用 700/900 字重 |
| 饼图配色由含青色跳色的五色改为同一苔绿梯度 | `PieChart.COLORS` | 原配色出现体系外青色，像随机调色 |
| 删除凭证页未使用的 `section`/`kv` 旧构建器 | `VoucherPage` | 死代码且使用体系外灰色 |
