# 成员上手与试用

建议一位成员负责环境和试用，另一位负责PPT；用相同的1.2.0协作候选。此文不包含虚构的试用结果。

## 1. 拉取与运行

仓库为私有时，先由负责人在 GitHub **Settings → Collaborators** 邀请你的GitHub账号；收到邀请后再克隆。仓库权限邀请由负责人操作，不要共享账号密码。

```sh
git clone https://github.com/huihui200739/lvtancunzhe.git
cd lvtancunzhe
```

纯业务验证不需要DevEco：`npm ci --ignore-scripts`，然后`npm test`。编译App前先运行`bash scripts/fetch-model.sh`下载端侧识别模型（11MB，不纳入Git）。

运行界面需要 DevEco Studio 和匹配 SDK。默认产品使用 API 24；使用 DevEco Studio 26 和 API 26.0.0 SDK 时可选择 `api26` 产品。打开仓库根目录，等待 OHPM 同步，在 Device Manager 启动对应手机模拟器。API 26 已完成基础模拟器验证，其余试用仍需执行，见[适配记录](API26适配记录.md)。

### macOS

```sh
bash scripts/setup-sdk.sh
./build.sh prod
```

自定义安装位置先设置`DEVECO_HOME`、`OPENHARMONY_SDK_HOME`，见README。脚本沿用本机已接受的SDK许可，不替你接受协议。

选择 API 26：设置 `DEVECO_HOME` 指向自己的 DevEco Studio 26 `Contents` 目录，`OPENHARMONY_SDK_HOME` 指向自己的 SDK 根目录，再设置 `GREEN_BUILD_PRODUCT=api26`，执行上面两条命令。`local.properties` 的 `sdk.dir` 也应指向相同 SDK 根目录。构建输出在 `entry/build/api26/outputs/default/`。

### Windows

使用英文工程路径。安装DevEco和API24 SDK，在DevEco的终端配置`NODE_HOME`、`OHOS_BASE_SDK_HOME`（也可同时设置`DEVECO_SDK_HOME`）为自己的安装/SDK目录，并确保工具目录在PATH中。SDK目录应有API版本目录，例如`24/ets`。

```powershell
ohpm install
hvigorw --mode module -p module=entry@default -p product=default -p buildMode=release assembleHap --no-daemon
```

若`hvigorw`未找到，使用安装目录`tools\hvigor\bin`下对应Windows启动器；若你的SDK目录结构不同，先在DevEco配置正确的OpenHarmony SDK，勿把别人的绝对路径照搬过来。Windows步骤为环境配置说明，本轮没有Windows实机验证。

如果使用 DevEco Studio 26 和 API 26，SDK 目录须包含 `26.0.0/ets`，将上述命令中的 `product=default` 改为 `product=api26`。Windows 的 API 26 构建尚未实测。

### 安装包

从 [1.2.0 团队试用版](https://github.com/huihui200739/lvtancunzhe/releases/tag/v1.2.0-team) 下载与设备环境匹配的 HAP，或按上文自行编译。新版已内置端侧模型和演示样张，不需要在设备上另外下载模型。

| 构建目标 | 团队试用包（独立 QA bundle） | 正式包名构建 |
|---|---|---|
| API 24 | `green-ledger-1.2.0-api24-qa-unsigned.hap` | `green-ledger-1.2.0-api24-unsigned.hap` |
| API 26 | `green-ledger-1.2.0-api26-qa-unsigned.hap` | `green-ledger-1.2.0-api26-unsigned.hap` |

QA bundle 为 `com.lvtancunzhe.qa`，正式 bundle 为 `com.lvtancunzhe.app`。四个包均为 release 模式，开发测试因子关闭，未签名；安装前用 Release 的 `SHA256SUMS.txt` 核对哈希，详细元数据见 [packages-1.2.0.json](evidence/packages-1.2.0.json)。API 24 / 26 的同类包共用包名，请按环境择一；试用及备份恢复只使用 QA 包与测试数据，勿覆盖维护者主库。常规物理设备仍需自行按 DevEco 配置匹配签名。

此前的 1.1.3 Release 保留为历史版本；API 26 的 1.2.0 构建已通过编译和包内容核验，尚未补做本版新增功能的原生运行验收。

在匹配的模拟器和调试环境中：

```sh
hdc list targets
hdc -t <设备ID> install -r <HAP完整路径>
hdc -t <设备ID> shell aa start -b com.lvtancunzhe.qa -a EntryAbility
```

最后一条是QA包入口；正式bundle对应`com.lvtancunzhe.app`。如果环境拒绝未签名包，请在自己的DevEco中配置调试签名再构建，不修改系统安全检查。HAP不能安装到普通Android手机上。

## 2. 试用任务（每人15—20分钟）

全程使用QA包和自己的测试数据。说明“这是功能试用、不是经核证的真实减排记录”；如填写假定数值，备注清楚“功能试用”，不能作为真实减排成果对外展示。电力录入表示**相对基准节约的电量**，不是总用电量。

| 顺序 | 任务 | 检查点 |
|---|---|---|
| 1 | 从存折进入节约能源，填1.25kWh，发生日为今天，注明测试；先试算再存入 | 河南因子0.5897时结果应为0.7371kgCO₂；数字与单位紧凑 |
| 2 | 打开该记录凭证，说出数量、因子、计算结果和边界 | 能区分申报、估算和核证；来源可追溯 |
| 3 | 修订数量，再查看版本与最新凭证；撤销最新版本 | 旧版本保留，统计更新、积分按规则冲正；已兑换可能出现待补足 |
| 4 | 在计划设定目标/预算，生成七日计划；修改目标但不重排，再观察提示 | “待修改”和已保存的旧计划分开，计划不会自动变成已完成记录 |
| 5 | 完成今天的核算任务或仅参与任务 | 日期和行动匹配；仅参与任务不新增kg |
| 6 | 看板切日/周/月/年，改日期但先不提交，再提交空区间和非法日期 | 旧统计不冒充新区间，空区间无异常 |
| 7 | 知绿打开一篇文章，描述图示与来源边界 | 不把CO₂与CO₂e相加 |
| 8 | 导出备份，新增一条测试记录，恢复刚导出的备份 | 新增测试记录消失、余额和计划按备份恢复；恢复会替换当前QA数据 |
| 9 | 关闭呼吸动效，重启；再检查系统大字体下的关键页面 | 偏好保留，无遮字或裁切 |
